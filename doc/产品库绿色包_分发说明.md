# 产品库绿色包（拷到别的电脑用）

> 生成时间：2026-10-06　　构建命令：`python tools/productlib/build_portable.py --clean --zip`

## 拿到的东西长什么样

```
集刻产品库_绿色包.zip          ← 发给别人 / 换电脑时用这个
└─ 集刻产品库/
   ├─ 启动产品库.cmd          ← 双击这个（双击入口）
   ├─ 启动产品库.ps1          ← 真正的启动脚本（端口占用自动避让）
   ├─ 使用说明.txt
   ├─ 集刻产品库.exe          ← 主程序（12MB）
   ├─ _internal/              ← 依赖（约 228MB，别删）
   └─ data/                   ← 数据（第一次运行自动建）
      ├─ productlib.db        产品库数据库
      ├─ standard/            标准图资产
      ├─ reports/             生成的装柜报告
      ├─ thumbs/  uploads/    缓存（可删，会自动重建）
```

**体积 240MB**，其中 cv2 112MB + onnxruntime 36MB 是图像识别/OCR 的依赖。

## 对方电脑要满足什么

- Windows 10/11（64 位）
- **不需要装 Python**
- 不需要联网（多模态识别没配 API key 时是降级模式，不影响其它功能）
- 浏览器（Edge / Chrome 都行）

## 三种用法

| 想干什么 | 怎么做 |
|---|---|
| 日常启动 | 双击 `启动产品库.cmd`，浏览器自动开 `http://127.0.0.1:8765/` |
| 换端口 | 命令行跑 `集刻产品库.exe --port 8800` |
| 换数据位置 | `集刻产品库.exe --data D:\某目录`，或设环境变量 `PL_HOME` |

启动脚本会在 8765~8768 里自动挑一个空闲端口——**老版本产品库没关是最常见的坑**，脚本会绕开它并在窗口里打印实际用的端口。

关掉那个黑色命令行窗口 = 关闭产品库。

## 数据怎么带走

**备份 / 换电脑：把整个 `data/` 文件夹拷走。** 里面是数据库 + 标准图 + 报告，全部业务数据都在这里。

⚠️ **但原照片不在这里。** 产品库对照片是「原地引用」——它只记照片在本机的路径，不把照片拷进 `data/`。所以：

- 换电脑后，照片批次需要**重新导入一次**（照片拷到新机器的哪个目录，就选哪个目录）
- 只拷 `data/` 的话：产品清单、柜、报告、标准图都在，但照片区会显示「文件不存在」

这一点没有更好的解法——900MB+ 的照片复制进库不是好主意，照片本来就该当只读资产看待。

## 重新构建

```powershell
python tools/productlib\build_portable.py --clean --zip
```

- `--clean`：处理掉旧的 `build/` `dist/`（**默认归档成 `.old`，不真删**；要真删加 `--yes`）
- `--zip`：额外打 zip（拷给别的电脑用）
- 脚本会自动挑一个依赖齐全的解释器并打印用的是哪个 —— 别拿没有 fastapi/Pillow 的 Python 去打包，会打出一个在别人机器上炸的包

## 踩过的坑（改 spec 前先看）

1. **不开 onefile**：每次启动都把 numpy/Pillow 解压到临时目录，冷启 10~20 秒，杀毒软件对自解压 exe 误报率高。onedir 冷启 1~2 秒。
2. **不开 UPX**：被杀软误报更狠，出问题时二进制也没法排查。
3. **`datas` 映射要去掉两级前缀**：源码是 `tools/productlib/web`，冻结分支按 `sys._MEIPASS/web` 找（少两级是源码布局的产物）。
4. **hiddenimports 必须列全 `tools.productlib.*`**：`routes/__init__.py` 是动态 `include_router`，静态分析可能漏，漏一个模块 = 那个功能页整块 404（页面能开、点进去报错）。
5. **`--data` 不能靠 `importlib.reload` 切路径**：路径常量在 import 期就定死，reload 会造出「库在新目录、缩略图还在旧目录」的半迁移状态。现在的做法是设环境变量后起子进程，并且**必须从 argv 里去掉 `--data`**，否则子进程又看到它、又重启，无限循环。
