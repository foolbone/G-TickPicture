# 集刻 · 产品库 —— 整体流程与界面改造方案 v5

> 触发：老板 2026-10-06 反馈的三条
> 1. 主流程要沿「创建柜子 → 导入清单 → 导入照片 → 照片治理 → 报告生成」连贯走完，以柜子为主体向导式推进；
> 2. 标准产品库、照片库、已生成报告是**资产**——既是工作成果，也是后续工作的基础；
> 3. 每个功能界面的操作逻辑要一致（建柜表单像筛选栏；导入页把输入和结果混在一起）。
>
> 前序文档：v1（`按柜号出装柜报告_设计方案_v0.17.0.md`）、v2（`...v2_产品库web端.md`）已作废；
> v3（`产品库柜号主线与装柜报告_设计方案_v3.md`）是本次的**数据底座**，本次只动交互层，不动 schema。

## 一、现状问题盘点（先把病灶点名）

### 1.1 主线被切成 4 个平级页，谁也不引导谁

| 主线步骤 | 现在在哪做 | 问题 |
|---|---|---|
| ① 建柜 | 「柜」页最上面一块内联表单 | 长得像筛选栏（见 1.3） |
| ② 导入清单 | 「标准产品库」页 phead 里一个「导入清单」按钮 | 藏在资产管理页右上角，不像流程 |
| ③ 导入照片 | 「预检照片库」页第一块 | 与治理、浏览三块竖着堆，页面很长 |
| ④ 照片治理 | 「预检照片库」页第二块（默认折叠） | 折叠=隐藏，新手不知道有这步 |
| ⑤ 生成报告 | 「报告中心」页三步选项卡 | 与①②③④完全割裂，要重新选一次柜 |

**结果**：五个动作散在四个页，没有一处告诉你"下一步是什么、还差什么"，只能靠人记住顺序。

### 1.2 资产没有"资产"的样子

- 标准产品库：只显示"这个产品有几张照片"，**看不出它来自哪个柜、被哪些柜的清单引用过**——而"跨柜复用"正是它最大的价值。
- 预检照片库：按批次筛选，**没有按柜筛选**；柜号是全流程主线，照片库却不能以柜为主视角。
- 已生成报告：只是报告中心第③步下面的一个小表格，没有独立的档案页，不能按柜检索。

### 1.3 界面操作逻辑三处不一致

**病灶 A —— 建柜表单内联在列表上方**
```
┌ 新建柜 ─────────────────────────┐   ← 像筛选条件栏
│ [柜号____] [封条号__] [客户__] [创建柜] │
└─────────────────────────────────┘
┌ 柜列表 ─────────────────────────┐   ← 下面紧接搜索"搜柜号/封条号"+筛选按钮
│ [搜柜号/封条号____] [筛选] [刷新]      │   ← 两个输入框排在一起，视觉上根本分不出哪个是"创建"哪个是"查"
└─────────────────────────────────┘
```
同一个 panel 区域里出现两排输入框 + 三个按钮，初次接触完全分不出「这是要我建东西」还是「这是要我筛东西」。

**病灶 B —— 导入页输入与结果混排**
- 标准产品库页：phead 里「导入清单 / 模板 / 补关联」三个按钮，紧跟着第二行「搜索 + 柜号筛选 + 状态筛选 + 排序」——**"往里灌数据的按钮"和"往外捞数据的筛选"物理上贴在一起**。
- 预检照片库页：导入表单行 → 治理折叠面板（进度条+诊断）→ 筛选条 → 照片网格。三种性质的东西（输入 / 长任务 / 结果）纵向堆在一屏里。

**病灶 C —— 柜选择没有统一锚点**
`loadContainerOptions()` 给每个 `.ctnSel` 各挂一份列表、各存一份 localStorage、各加一个 change 监听器。于是三处柜下拉**各选各的**：在报告中心①选了 A 柜，②取材还是 B 柜（此前已修过一次，但架构上仍是"三份真相"）。

## 二、改造目标与三条硬原则

### 目标
1. **一条主线**：一个向导页走完 ①→⑤，柜号从头贯到尾，中途不用重新选。
2. **三类资产**：产品库 / 照片库 / 报告档案 = 累积资产，可查、可筛、可跨柜复用。
3. **一套骨架**：所有页面用同一种结构，用户学会一个页就会用全部页。

### 硬原则（写进代码评审清单）

| # | 原则 | 含义 |
|---|---|---|
| **P1** | **一个真相源** | 柜号只有一份：顶栏的**全局柜锚点**。其它地方只读展示，或切换它。禁止各存各的 localStorage。 |
| **P2** | **写操作走模态** | 所有「创建 / 导入 / 生成」类动作**不内联表单**，一律点按钮 → 模态 → 填 → 提交 → 关模态 → 结果区刷新。 |
| **P3** | **输入与结果分离** | 页面上「筛选」只改显示、「动作」只改数据，两者**视觉分区**（筛选有独立底色/分隔线，主操作按钮固定在标题区最右）。 |
| **P4** | **向导可中断可回看** | 步骤状态由数据派生（不是 localStorage 记账），关掉浏览器回来还是那一步；已完成步骤随时回看。 |
| **P5** | **闸门说人话** | 前置不满足时按钮禁用，并**说明缺什么、去哪补**。禁止静默失败。 |

## 三、目标信息架构

### 3.1 顶栏：全局柜锚点

```
集刻 · 产品库   当前柜 [EMCU9914616 ▾]  ●就绪 45%      产品 785 · 照片 2738    多模态：已配置
                 └── 唯一真相源 ──┘   └── 就绪度 ──┘
```

- `#globalCid` 是**唯一**的柜选择器；写入 `localStorage['plCid']`。
- 所有旧的 `.ctnSel` 下拉：
  - 向导页 / 报告页 → 直接删掉，改为只读展示「本柜：EMCU9914616」。
  - 资产页 → 改为「按柜筛选（默认全部）」，这是筛选，不参与锚点。
- 提供 `core.js` 三件套：`getCid()` / `setCid(id)` / `onCidChange(fn)`；锚点变化广播给所有页。

### 3.2 导航：从 7 项收到 6 项，并分组

```
作业     作业向导
资产     柜 | 标准产品库 | 预检照片库 | 报告档案
其他     设置
```

| Tab | 作用 | 变化 |
|---|---|---|
| **作业向导**（新，默认首页） | 5 步向导，走完一柜的全部动作 | 新增 |
| 柜 | 柜资产总览：所有柜 + 就绪度 + 元数据维护 | 内联建柜表单 → 「+ 新建柜」按钮（模态） |
| 标准产品库 | 产品资产（跨柜）+ 标准图维护 | 导入按钮 → 模态；加「来源柜 / 被引用」 |
| 预检照片库 | 照片资产 + 打标浏览 | 导入按钮 → 模态；治理面板移到向导④；加「按柜筛选」 |
| 报告档案 | 历史报告资产 | 从报告中心③拆出独立页；加「按柜筛选」 |
| 设置 | 多模态 / 落盘 / 字典 | 不变 |

**「新产品确认」不再单独占 tab** —— 它是第④步「照片治理」的一个待办子项，从向导④的徽章进入（section 保留，可从向导与柜详情跳转）。

### 3.3 职责切分：向导 = 写，资产页 = 读

```
         ┌─────────── 作业向导（改变数据）───────────┐
         │ ①建柜 ②导清单 ③导照片 ④治理 ⑤生成报告      │
         └───────────────┬───────────────────────────┘
                         │ 产出
         ┌───────────────▼───────────────────────────┐
         │ 资产页（查看 / 检索 / 逐条维护）            │
         │ 标准产品库 · 预检照片库 · 报告档案            │
         └───────────────────────────────────────────┘
```

- **每个"写"动作在全局只有一处入口**（在向导里）。
- 资产页只保留**逐条维护**（产品详情抽屉里改字段、裁标准图；照片抽屉里打标）——这是"维护"，不是"流程动作"。
- 资产页顶部提供「回到向导第 N 步」的反向链接。

## 四、作业向导详细设计

### 4.1 步骤条

```
  ①建柜 ━━━━ ②导入清单 ━━━━ ③导入照片 ━━━━ ④照片治理 ━━━━ ⑤生成报告
   ✓         ✓          ○           ○            —
 已完成     12 行       128 张      待治理 36     未生成
```

- 横向步骤条，5 个节点；状态四态：`done(✓)` / `todo(○)` / `blocked(—)` / `current(高亮)`。
- 节点下直接写**该步的关键数字**（同源：来自 `/api/containers/{cid}/progress`）。
- 点击任一节点切换下方内容面板；`blocked` 节点可点但面板里说明缺什么。

### 4.2 每步卡片统一结构

```
┌─ ② 导入清单 ──────────────────────────── [已完成] ─┐
│                                                     │
│  说明：把货品清单（Excel）导入到柜 EMCU9914616。      │  ← 一句话：做什么
│        清单行会进报告的 Packing list 与 Quantity check│
│                                                     │
│  ┌ 本步状态 ────────────────────────────────────┐   │
│  │ 清单行 12 · 未核对 4 · 清单批次 1              │   │  ← 数字（与本页同源）
│  └──────────────────────────────────────────────┘   │
│                                                     │
│  [选择 Excel 导入]  [下载模板]      ← 主操作（左）    │
│                                                     │
│  查看资产 → 标准产品库                    ← 反向链接  │
└─────────────────────────────────────────────────────┘
```

要点：
- **卡片里不放结果表格**。导入结果用 toast + 卡片内"本步状态"数字变化呈现；要看明细去资产页。
- 主操作按钮**固定在卡片底部左侧**，次要操作在右。
- 反向链接统一文案「查看资产 → XXX」。

### 4.3 五步逐条规格

#### ① 建柜
- **前置**：无。
- **状态**：`柜号 · 封条号 · 客户 · Inspector`（缺项用橙色标出，因为要进报告 General Information）。
- **动作**：
  - `[+ 新建柜]` → 模态（柜号 \*必填 / 封条号 / 客户 / Inspector / Location / 到柜时间 / 离柜时间）。创建成功后**自动设为当前柜**并刷新锚点。
  - `[切换柜]` → 直接切到顶栏锚点下拉。
- **卡片里嵌一个"最近 5 个柜"的小列表**，点行即切换锚点（比只给下拉好找）。

#### ② 导入清单
- **前置**：已选柜，否则按钮禁用 + 说明「先完成①建柜」。
- **状态**：`清单行 N · 未核对 M · 清单批次 K`。
- **动作**：
  - `[选择 Excel 导入]` → 模态：显示「将导入到柜 **EMCU9914616**」（只读，取自锚点）→ 选文件 → 导入（busy 进度）。
  - `[下载模板]`。
- **结果**：toast 摘要（新增 X / 更新 Y / 跳过 Z / 错误 N 行）；卡片状态数字刷新。

#### ③ 导入照片
- **前置**：已选柜。
- **状态**：`照片 N 张 · 批次 K · 预检 a / 监装 b`。
- **动作**：
  - `[选择目录]` / `[上传文件]` → 模态（柜只读展示 + 目录输入框/文件多选）。
- **特别说明**（写进卡片）：支持标准采集格式 `{柜号}/预检/{箱号}/照片.jpg`；**柜号以这里选的柜为准**，目录名不影响归属，程序不会自动建柜。
- **提示**：若清单还没导，给一条橙色提示「建议先完成②——清单先于照片导入时，自动关联才能命中」。

#### ④ 照片治理
- **前置**：本柜有照片。
- **状态**：`已治理 X/Y · 待确认 Z · 失败 W · 已关联 L`。
- **动作**：
  - `[开始治理]` → 进度条 + 诊断面板（**整体搬现有 `batches.js` 治理面板**，含批次选择 / 重试失败 / 重新治理 / 失败七类诊断）。
  - 待办徽章：`待确认 Z 项` → `[去确认]`（跳「新产品确认」section，带返回）。
  - 待办徽章：`柜况图 a/4 · 卡车头 缺` → `[去打标]`（跳照片库，按柜+监装预筛）。

#### ⑤ 生成报告
- **前置**：本柜有清单行 ≥1（无清单直接给出明确拒绝理由）。
- **状态**：`已生成 N 份 · 最近 2026-10-06 17:20`。
- **动作**：
  - 可折叠的「取材（可选）」：粘贴/载入本柜清单编码 → 检索 → 标记采用（现有 report.js ②逻辑，柜跟随锚点，不再有第二个柜下拉）。不取材则每件货自动取一张。
  - 选项：⑥倒序（默认开）/ 用取材图（默认开）/ 画质（1200 默认）/ 模板。
  - `[生成 docx]` → busy → 结果卡（文件名 / 大小 / 下载 / 打开所在目录）。
- **底部**直接列出本柜历史报告 3 条 + 「查看全部 → 报告档案」。

## 五、统一页面骨架（Page Pattern）

任何功能页一律四段，缺哪段就空着，但**顺序和位置不许变**：

```html
<section id="tab-xxx">
  <!-- ① 标题区：页面名 + 一句话定位 + 主操作（唯一，最右） -->
  <div class="phead page-head">
    <h2>标准产品库<span class="sub">跨柜复用的产品资产</span></h2>
    <span class="spacer"></span>
    <button class="btn" data-act="import">+ 导入清单</button>   <!-- 开模态 -->
    <button class="btn ghost sm" data-act="reload">刷新</button>
  </div>

  <!-- ② 资产概览：4 个数字卡（总数 / 关键缺口 / 最近更新 / 存储占用） -->
  <div class="cards" id="xxxCards"></div>

  <!-- ③ 筛选条：只改显示，不动数据；有独立底色与上下分隔线 -->
  <div class="toolbar">
    <input type="text" placeholder="搜…"> <select>…</select>
    <button class="btn ghost sm">重置</button>
    <span class="spacer"></span><span class="faint">共 N 条</span>
  </div>

  <!-- ④ 结果区：只读；点行开抽屉；空态三件套 -->
  <div class="scroller"><table><tbody id="xxxBody"></tbody></table></div>
  <div class="empty" id="xxxEmpty">…</div>
  <div class="pager" id="xxxPager">…</div>
</section>
```

### 5.1 元素位置与行为对照表（全站执行）

| 元素 | 位置 | 外观 | 行为 |
|---|---|---|---|
| **主操作**（新建 / 导入 / 生成） | 标题区最右 | `.btn` 实心蓝 | **开模态**；提交成功→关模态→刷新结果区→toast 摘要 |
| **次要操作**（模板 / 刷新 / 重置） | 主操作左侧 | `.btn.ghost.sm` | 直接执行 |
| **筛选控件** | 筛选条（独立底色） | 原生控件 | 只改显示；改动后即时刷新结果区；**绝不写库** |
| **结果表格 / 网格** | 结果区 | 只读 | 点行 → 详情抽屉 |
| **逐条维护**（改字段 / 裁图 / 打标） | 抽屉内 | 表单 | **显式保存**；有未保存改动时离开拦截 |
| **破坏性操作**（删除） | 抽屉 / 行内 | `.btn.danger` | 二次确认，说明后果与是否可恢复 |
| **空态** | 结果区 | `.empty` | 图标 + 一句话 + 下一步按钮 |

### 5.2 统一模态（`web/static/js/modal.js`，新建）

```js
openModal({
  title: '新建柜',
  bodyHtml: '...',          // 表单；字段用 name 属性
  okText: '创建',
  danger: false,            // true → 确认按钮变红
  width: 520,
  onOk(values) { ... }      // 返回 false / 抛错 → 不关闭；抛错在模态内显示错误
})
```
- Esc / 点遮罩 / 取消 → 关闭（有未保存改动时确认）。
- 表单错误在模态内就地显示，不用 toast。
- 用途：新建柜、导入清单、导入照片、生成报告选项、删除确认。

## 六、资产化改造

### 6.1 标准产品库
新增两列（跨柜复用可视化）：
- **来源柜**：产品第一次被哪个柜的清单带进来（由 `products.source_batch → batches.container_id` 反查）。
- **被引用**：有多少个柜的清单行引用了这个编码（`checklist_rows.code_norm` 去重计数），hover 显示柜号列表。

顶部概览卡：`产品总数 / 有标准图 / 无图 / 跨柜复用率`。

### 6.2 预检照片库
- 筛选条新增**「柜号」下拉**（默认全部，可跟随顶栏锚点一键"切到当前柜"）。
- 批次下拉的 option 文案带上柜号前缀：`EMCU9914616 · 2026-09-27 14:03`。
- 保留：状态 / 分类 / 用途 / 未关联 / 关键词 / 视图切换。
- 治理面板**移除**（搬到向导④），原位放一个「跑治理 →」按钮（带当前批次参数跳向导）。

### 6.3 报告档案（新页，从报告中心③拆出）
- 表格列：报告文件 / 柜号 / 大小 / 生成时间 / 操作（下载 / 删除 / 打开所在目录）。
- 柜号从文件名解析：`LOADING REPORT-CNTR#<柜号>-<日期>.docx`（不新增表，零迁移风险）。
- 顶部概览卡：`总份数 / 占用空间 / 本月新增 / 已归档柜数`。
- 筛选：按柜号 + 文件名关键词。

### 6.4 柜页
- 内联建柜表单 → 标题区「+ 新建柜」按钮（模态）。
- 列表列：柜号 / 封条号 / 清单行 / 照片 / 就绪度进度条 / 操作（详情 / 出报告）。
- 「出报告」→ 设锚点为该柜 → 跳向导⑤。

## 七、后端改动清单

### 7.1 新增

## 十一、风险与"不做什么"

| 项 | 处置 |
|---|---|
| 老数据丢失 | **不改 schema、不动迁移链**，v3 的幂等迁移已验证；升级前用 `集刻产品库.exe --upgrade` 备份整个 `data\` |
| 步骤状态记账漂移 | 状态**派生自数据**（行数 / 治理数 / 报告文件数），不落 localStorage 记账 |
| 治理面板重复维护 | 抽成可挂载组件，向导④与照片库共用同一份实现 |
| 前端契约检查变假绿 | 改完 `index.html` / 新增 js 后**必须**重跑 `web_contract.py`，并用"加一个假 id 看它是否报红"的探针验证检查器真的在工作 |
| 打包漏文件 | 新增 `wizard.js` / `modal.js` 是静态资源，`productlib.spec` 的 datas 已收整个 `web/`，无需改；但需重跑 `build_portable.py` 并核对产物里两个新文件存在 |

### 明确不做
- 不动 App（Flutter）端任何代码；
- 不改 `report_gen.py` 的版式与图框参数（上轮刚定稿）；
- 不新增数据库表；
- 不做登录/权限（本机单人工具定位不变）。

## 十二、待确认（动手前请老板拍板）

1. **向导形态**：横向 5 步步骤条（一屏一步，点节点切换）vs 纵向 5 张卡片（一屏全见）——建议**横向步骤条**，页面短、进度感强。

4. **就绪度口径**：⑤生成报告的前置是「有清单行 ≥1」还是「清单行 ≥1 且照片 ≥1」？——建议**清单 ≥1 且照片 ≥1**，否则报告会是空的。
5. **向导是否自动跳步**：完成②后自动切到③，还是停在原地等用户点？——建议**自动跳下一步**（向导感更强）。
