# 产品库系统重构方案（2026-09-27）

> 定位：整合分散功能，统一信息架构，让「导入照片 → 审核入库 → 检索匹配 → 生成报告」成为一条连贯主流程。
> 本方案基于对 tools/productlib/ 全部 9 个模块（4844 行 Python + 1450 行前端）的通读盘点。
> **注**：六页信息架构、批次一等公民、报告素材检索/导出已于 09-27 上午落地并验证通过。
> 本方案 = 现状盘点 + 差距补齐，不推倒重来。

---

## 一、现状盘点

### 1.1 模块划分（tools/productlib/）

| 模块 | 行数 | 职责 |
|---|---|---|
| schema.py | 238 | 数据规范 + DDL（7 表 + runs 日志） |
| store.py | 903 | **唯一写入口**：产品/照片导入、关联、发现新产品、合并建议、标准图、标准库导出、批次统计、报告素材 |
| pipeline.py | 425 | 治理管道（分类→分路→OCR/多模态→自动关联）、语义候选、按批次治理、重复继承 |
| vision.py | 312 | 多模态 provider（OpenAI 兼容、可插拔、未配 key 降级、enable_thinking=False） |
| server.py | 900 | FastAPI ~30 端点 + 后台治理线程 + 缩略图缓存 |
| web/index.html | ~1450 | 六页 SPA（单文件，CSS 变量 + 抽屉 + canvas 标准图编辑器） |
| cli.py | 156 | 命令行（stats / import-checklist / import-photos / govern / link / show） |
| selftest.py | 230 | 独立测试库端到端自检（S1~S10，覆盖五条构建逻辑） |
| build_library.py（复用） | 1666 | 共享底层：normalize/CodeIndex/parse_checklist/merge_items/scan_photos/OCR |

### 1.2 页面结构（当前六页，已上线）

概览（两大工作区引导）/ 标准库·产品（master-detail + 落盘导出）/ 审核队列（甲·关联认领 + 乙·发现新产品 + 丙·合并裁决）/ 预检批次（批次表 + 治理面板 + 批次过滤网格）/ 报告素材（清单提码 + 批次多选 + 检索矩阵 + 素材包导出）/ 设置（多模态 + 数据规范）。

### 1.3 数据模型

- **products**：`code_norm` 主键（归一化与 APP 侧 code_matcher.dart 对齐），photo_count/auto_count/manual_count 由 links 现算，review_state（confirmed/待审核）。
- **batches**：kind=checklist/photos，name/note（JSON 统计）/item_count/created_at。
- **photos**：batch_id、taken_at、md5（is_dup/dup_of 去重继承）、govern_state、photo_kind、vision_desc/codes。
- **links**：code_norm↔photo_id，source（auto_ocr/auto_vision/manual）+ confidence + evidence + created_by，UNIQUE 约束。
- **standard_images**：code_norm + src_photo_id + kind + file，一照片可多版本（created_at 秒级精度 → rowid 定序）。
- **discover_ignore / ocr_tokens / runs**。

### 1.4 治理规则（已实现的数据治理）

去重：MD5 逐字节（实测 249 张抓出 13 张副本，副本跟随原图不重复治理）；清洗：全角→半角、分隔符删除、形近字纠偏（O/I/L/S，只留精确纠偏，模糊进人工）；编码归一：normalize=upper+去分隔符，归一后≥4 位且含数字才可入库；自动关联纪律：仅 exact 且 ≥0.70 才自动写，模糊一律进人工。

## 三、差距补齐方案（本轮实施内容）

### G1 标准图版本管理（零迁移）
- 后端：无改动。`GET /api/standard-images?code=`、`DELETE /api/standard-images/{sid}` 均已存在。
- 抽屉「标准图」区块增强：列出该产品已有标准图缩略图（按 src_photo_id 过滤当前照片），标注「当前生效」（=最新版）与历史版本，历史版本可删除。
- 产品页照片网格：做过标准图的照片卡加「标」角标（pShots 渲染时带 has_std 标记——后端 /api/products/{code}/photos 附 standard_photo_ids 集合，一处小改）。

### G2 素材导出尺寸压缩（零迁移）
- `store.report_export(..., long_edge=1600)`：Pillow 等比缩放，long_edge=0 表示原图（默认 1600，与标准图规格一致）。
- 报告素材页导出面板加「长边 1600 / 2048 / 原图」选择。
- CSV 增加一列记录实际导出尺寸。

### G3 推荐标签补全：最接近标准参考图 + 理由（零迁移）
- 该产品存在标准图时启用：pHash（Pillow 32×32 灰度 + 简化 DCT，64bit）计算候选照片缩略图与标准图的汉明距离，距离最小者加「近标准图」标签（+0.12）。
- 每张候选生成 reason 文案数组：如「做过标准图，导出优先」「该货品最新拍摄」「分辨率最高」「与标准参考图最接近（汉明距 n/64）」。
- 前端标签 hover 显示理由；矩阵卡上展示首条理由。

### G4 检索结果人工替换（零迁移）
- lookup 响应不变；前端矩阵内每张候选加「设为采用」按钮 → 记入 `_rpPick[code]=photo_id`，实时更新 recommended 标记。
- 导出 body 增加 `picks: {code: photo_id}`；`report_export` 有 picks 的编码用指定照片，其余按 top1。人工选择在 CSV 状态列记「人工指定」。

### G5 生成报告（待拍板后实施，若确认）
- 方案：导出时同时生成 `report.html`（单文件、内嵌缩略图 base64、深海军色打印 CSS、按货品分节：编码/品名/规格/采用图+备选图缩略）。浏览器打开即可 Ctrl-P 出 PDF。
- 不做 Word/PDF 二进制生成（依赖重、收益低）；HTML 可打印已满足评审/存档场景。

## 四、主流程串联（实施后）

```
导入照片(按批次,自动去重) ──► 治理(分类/OCR/多模态,可按批次跑) ──► 审核队列
                                                                  ├─ 甲 关联认领（照片→已有产品）
                                                                  ├─ 乙 发现新产品（确认→新增条目）
                                                                  └─ 丙 合并裁决（模糊命中→人工拍板）
                                                                        │
        导入货品清单(粘贴/xls) ──► 报告素材检索(标准库+指定批次) ◄──┘
              │                        │  标签:标准图/最新/高清/近标准图 + 理由
              │                        ├─ 一键替换采用 / 默认 top1
              │                        └─ 导出素材包({序号}_{编码}/ + CSV [+ report.html])
              └──► 每步缺口(无码/无图/无匹配)红卡可见，不静默丢弃
```

## 五、兼容与迁移策略

- **零 schema 迁移**：G1~G4 全部用现有表与接口增量实现；photos/standard_images 结构不动。
- 既有能力全保留：CLI、selftest、降级模式（无多模态 key 照常跑）、原始文件永不改名/不移动。
- 老库直接可用（556 产品 / 1466 照片 / 2 批次实测库即验证库）。
- selftest.py 增补 2 条断言（S11 报告素材检索含 picks、S12 导出压缩），保持端到端可回归。

## 六、端到端验证计划

1. 临时库单测：pHash 稳定性（同图距离 0）、picks 覆盖 top1、long_edge 压缩生效（导出文件 bytes < 原图）。
2. node --check + id 一致性校验（沿用现有脚本）。
3. 真实库冒烟：lookup 带「近标准图」标签、picks 导出命中人工选择、压缩后文件尺寸对比。
4. 全流程人工走查：导入 20 张小批次 → 治理 → 审核队列清零 → 报告素材页用 manifest_4_004c0e.xls 检索 → 导出 → 打开 report_index.csv 核对。
