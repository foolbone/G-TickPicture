# 产品库升级指南（换绿色包时怎么保住之前的数据）

> 结论先说：**升级不会丢数据。** 但必须按下面的步骤走，别直接解压覆盖。

## 一、你的数据在哪里

绿色包里**只有 exe 和依赖是程序**，你的数据全在同一个文件夹的 `data\` 里：

```
集刻产品库\
├─ 集刻产品库.exe        ← 程序（升级时才换）
├─ _internal\            ← 程序依赖（升级时才换）
├─ ocr\                  ← OCR 模型（升级时才换）
├─ 启动产品库.cmd        ← 启动入口
├─ 升级助手.py           ← 升级工具（本次新增）
└─ data\                 ← ★ 你的全部数据，升级时**整个拷走**
   ├─ productlib.db      产品、清单、柜、关联（核心数据库）
   ├─ standard\          标准图资产
   ├─ reports\           生成的装柜报告 docx
   ├─ thumbs\            缩略图缓存
   ├─ uploads\           上传临时文件
   └─ vision.json        视觉模型配置（**API Key 在这里，务必拷**）
```

## 二、升级三步

1. **把新版本解压到另一个目录**（比如 `集刻产品库_新版\`）
   —— 不要覆盖老目录！覆盖会把程序文件弄乱，出问题连回退的余地都没有。
2. **把老版本的 `data\` 整个文件夹拷进新目录**
   —— 整个拷，不要只拷 `productlib.db`。标准图、报告、缩略图、API Key 都在里面。
3. **双击新目录里的「升级助手.py」**（或命令行跑 `集刻产品库.exe --upgrade`）
   —— 它会依次做：备份 → 升级库结构 → 逐表核对行数 → 报告结果。

⚠️ **升级前先关掉产品库**（黑色命令行窗口关掉）。开着的时候两个进程可能同时改表。

## 三、升级助手做了什么（为什么安全）

| 步骤 | 做什么 | 为什么安全 |
|---|---|---|
| 1. 备份 | 把整个 `data\` 复制成 `data_备份_20261006_171059\` | 有还原点。**复制目录而非单文件**，缩略图/报告都能还原 |
| 2. 升级 | 用新代码打开库，触发迁移 | 迁移里**只有** `CREATE TABLE IF NOT EXISTS` 和 `ALTER TABLE ADD COLUMN`（都带幂等探针）——**没有任何 DROP / DELETE / 改已有数据** |
| 3. 自检 | 逐表比对升级前后的行数 | 掉行会明确报出来并给还原步骤 |
| 4. 冒烟 | 实际读一次库 | 抓「建好了但读不了」的情况 |

### 实测结论（在你真实库副本上跑的）

```
升级前：12 张表 / 25002 行
备份：  114.6 MB（8 秒）
升级：  0.27 秒
自检：  batches 21→21 · checklist_rows 1003→1003 · containers 3→3
       links 1017→1017 · ocr_tokens 17377→17377 · photos 2738→2738
       products 785→785 · standard_images 4→4 ...
       [ OK ] 逐表行数核对通过：没有任何一张表掉行
```

还额外验证了**迁移幂等**：强制重跑迁移 3 次，每张表行数完全不变
（所以中途失败再启动一次也不会坏）。

## 四、出问题怎么还原

1. 关掉产品库
2. 把当前 `data\` 改名成 `data_坏的\`（**别删**）
3. 把 `data_备份_时间戳\` 改名回 `data`
4. 重新双击 `启动产品库.cmd`

## 五、真正需要你注意的一件事

**照片本身不在 `data\` 里。** 产品库对照片是「原地引用」——它只记照片在本机的路径。

所以：

| 场景 | 照片会怎样 |
|---|---|
| **同一台电脑升级** | ✅ 路径不变，照片照常能用 |
| **换一台电脑** | ❌ 路径失效，需要把照片拷到新机器，再重新导入照片批次 |

`upgrade.py` 会抽查 20 张照片告诉你原路径还在不在，并明确提醒这一点。

产品、清单、柜、关联、报告、标准图、API Key —— 这些**换电脑也不会丢**，它们全在 `data\` 里。

## 六、命令速查

```powershell
# 看看会做什么（不改任何东西）
python tools/productlib\upgrade.py --data "D:\某电脑\集刻产品库\data" --dry-run

# 真升级（自动先备份）
python tools/productlib\upgrade.py --data "D:\某电脑\集刻产品库\data"

# 绿色包里（没有 Python，用 exe 自己跑）
集刻产品库.exe --upgrade
集刻产品库.exe --upgrade --dry-run
```

## 七、常见误区

| 做法 | 后果 |
|---|---|
| ❌ 直接解压新包覆盖老目录 | 程序文件可能新旧混装；出问题时没有干净的回退点 |
| ❌ 只拷 `productlib.db` | 标准图、报告、缩略图、**API Key** 全丢 |
| ❌ 升级时产品库还开着 | 两个进程可能同时改表结构 |
| ❌ 升级前不做备份 | 出问题就只能重录所有数据 |

## 八、v5 这版要不要走升级流程（2026-10-06）

**要**——但不是因为数据结构变了。

v5 是**纯交互层改造**（作业向导 + 统一模态 + 资产页骨架），明确做到了：

- **不动 `schema.py` 的建表与迁移链**（一行没改）；
- 后端只加了 1 个只读端点 `GET /api/containers/{cid}/progress`、
  给既有接口加了可选参数与返回字段（**只增不减不改名**）；
- 向导的每一步状态**派生自数据**（清单行数 / 治理数 / 报告文件数），
  不写库、不落 localStorage 记账 —— 所以老数据进来立刻就有正确的就绪度。

所以升级完**不需要任何数据修补**，也不用重新导清单 / 照片 / 重跑治理。

升级后你会看到的变化（提前说一声，免得以为出错了）：

| 变化 | 说明 |
|---|---|
| 打开就是**作业向导** | 五步走完一柜：建柜 → 导清单 → 导照片 → 治理 → 报告 |
| 「新产品确认」不在导航里了 | 它不是独立流程，是第④步治理的一个待办项，从向导④的徽章进去 |
| 「报告中心」改名**报告档案** | 生成入口并到了向导⑤，这里看历史报告（按柜、可下载） |
| 建柜 / 导清单 / 导照片改成弹窗 | 原来内联在列表上方的表单取消了，点按钮 → 弹窗 → 填 → 提交 |
| 顶部多了「当前柜」选择器 | 全站**只有这一处**能定柜号，切一次全流程都跟着换 |
| ✅ 新目录 + 拷 data + 跑升级助手 | 有备份、有行数核对、有还原步骤 |

## 九、10-07 这两条改动要不要走升级流程（2026-10-07）

**不需要**，同样是零 schema 改动：

| 改动 | 落点 | 数据影响 |
|---|---|---|
| 照片按「已关联 / 未关联」分组展示 | 前端新增「关联」视图 + 向导③的「按关联分组」开关 | 无 |
| 报告每页 6 张图、章节另起一页 | `report_gen.py` 版式常量与分页符 | 无（只影响**新生成**的报告） |

- `GET /api/photos` 多了一个**可选**查询参数 `linked=1`，老调用方不传行为不变；
- 报告版式改动**只在下一次点「生成报告」时生效**，已生成的 .docx 不会被改动 ——
  想看新样式，重新生成一柜即可（同名文件会覆盖，被 Word 打开时会自动加时分秒另存）。

### 10-07 第二轮（同属零 schema 改动）

| 改动 | 说明 |
|---|---|
| 「预检照片库」改名「**照片库**」 | 只是名字，数据没动 |
| 顶部两块说明收进「说明 ▾」 | 默认收起，导入/治理两个入口仍常驻在标题行 |
| 照片多两档分组：**待确认关联** / **新产品确认** | 复用既有口径，不新建表 |
| 报告每页 6 张图、章节另起一页 | 只影响**新生成**的报告 |

新增两个只读端点（老调用方不受影响）：

- `GET /api/photos/linkstate` —— 五档分组计数，选项卡徽章用；
- `GET /api/photo-flags?ids=` —— 卡片「待确认 / 新产品」角标（前端异步补，首屏不等它）。

⚠️ 顺手修了一个既有 bug：重复件（`is_dup=1`）之前会出现在新产品候选里，
现在排除了。**如果你之前在「新产品确认」页确认过一个重复件，不影响已入库的产品。**
