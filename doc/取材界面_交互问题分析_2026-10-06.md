# 取材功能（报告中心②）交互与可用性问题分析

> 2026-10-06 凌晨 · 老板要求：分析取材界面在交互和使用上的问题。
> 分析视角：**这一步的目的是给报告⑥选照片**（v4 定位），不是通用检索工具。
> 每条问题都基于当前代码实测行为，不是猜测。

---

## 先说结论

取材界面是「预检照片检索」时代几乎原样搬过来的，**心智模型还停留在"检索工具"**，
和新的"报告流水线"定位有三处根本性冲突（P0）；另有十处具体交互问题。

## P0：结构性问题（心智模型冲突）

### 1. 「检索范围」与报告无关，但看起来有关 —— 误导

**现象**：左侧有「检索范围」面板（批次勾选 / 只选最新 / 全库检索），用户自然认为
"我在这里选的范围决定报告用哪些照片"。
**事实**：报告⑥的照片 = **该柜的 links + picks**，与检索范围**零关系**。检索范围
只影响②里展示什么。勾掉所有批次，报告照样 252 张。
**危害**：用户会花时间调整批次范围以为在"控制报告"，白费功夫；更糟的是反向——
用户以为不勾批次报告就没图，不敢动。
**修法**：检索范围降级为「结果过滤」；默认自动锁定①选的柜（只搜该柜批次）。

### 2. 两个柜选择器互不同步 —— 同页两个"当前柜"

**现象**：①有 `#lrContainer`（生成用），②里又有 `#rpChecklistBatch`（加载清单用），
两个独立下拉、各自记忆，可以选成两个不同的柜。
**事实**：实测确认两者无联动代码。
**危害**：①选了 EMCU、②加载了 UETV 的清单 → 取材的全是错的柜的编码；picks 又是
编码维度，会把 UETV 的采用图带进 EMCU 的报告（同码时真会发生）。
**修法**：②跟随①——①选柜后，②自动加载该柜清单编码（可关掉），删掉第二个柜下拉。

### 3. 缺口提示与报告就绪度脱节 —— 两套"缺什么"

**现象**：②检索显示「缺口 139 个」（其中一部分只是"照片不在所选批次"的假缺口）；
①就绪度又显示另一套（核对照 252 / 柜况图 0/4）。两处口径不同、位置分离。
**危害**：用户看到 139 缺口会慌，以为报告出不了——但报告根本不需要检索命中，
它只看 links。139 里很多"照片在别的批次"的假缺口对报告毫无影响。
**修法**：②的缺口措辞区分「对报告有影响」（该编码柜内无 links）与「仅检索显示问题」；
数字口径直接复用 ①就绪度 的同一份数据（铁律 23）。

## P1：高频操作的具体障碍

### 4. 点「设为采用」整屏重渲染 —— 闪烁 + 图片重新加载

`renderRpResult(_lastRp)` 全量 innerHTML 重建（report.js:212）。每采用一张，
446 个卡片、上千张缩略图全部重建；懒加载图片重新触发，肉眼可见闪烁；
滚动高度变化导致跳动。连点几张非常难受。
**修法**：只更新被点的两个卡片（当前卡 + 新采用卡）的 DOM 状态类。

### 5. 编码池没有管理能力

- 446 个 chips 挤在 **140px 高**的滚动框里（`.rp-codes-wrap{max-height:140px}`），
  找一个编码只能肉眼扫或 Ctrl+F
- 无搜索框、无「只看未命中」、无分组、无批量清空某来源（比如"只清掉粘贴进来的"）
- **无批量操作**：想把 307 个命中全部"采用建议的一张"，得点 307 次
**修法**：编码区加搜索 + 计数（命中/缺口/已采用）；加「全部采用建议图」一键。

### 6. 检索没有 loading 反馈

`#rpGo` 点击后只有按钮 disabled（视觉上几乎无变化），大库检索数秒内界面无任何
进度表示。违反"耗时流程必须有进度"的既有教训。
**修法**：按钮转圈 + 结果区显示「检索中…」骨架。

### 7. 结果区太长且没有过滤

- 缺口置顶排序（导出时代的设计），139 个缺口卡把 307 个命中压到千里之外——
  而**取材的目的是看命中的照片**
- 无「只看命中 / 只看缺口 / 只看已采用」过滤，无分页/折叠
**修法**：默认折叠缺口（一行摘要 + 展开）；顶部加过滤 chips。

### 8. picks 无跨柜隔离、无生命周期

- `_rpPicks` 按 code_norm 存，切到另一个柜生成时原样带上（前端不清理）
- 换柜不清 picks；刷新页面**全部丢失**且无提示（离开拦截的既有规范没覆盖这里）
**修法**：picks 绑定柜（切换时确认）；生成后提示是否清空；刷新前有未采用完的
picks 时弹离开确认。

## P2：小问题（顺手修）

9. **③的「⑥用取材选中的照片」开关离②太远**——在②采用时应就地提示
   "已采用 N 张，将用于报告⑥"，让连接可感知（现在完全静默）。
10. **缺口卡的「不限批次重检」会清空所有勾选**——不可逆且无确认。
11. **素材包导出面板**只有检索后才出现，但没有任何"为什么现在出现了"的解释；
    目录记忆是全局的，不跟柜。
12. **同一功能两个入口**：「按柜号加载清单」与「从清单表提取」都能拿编码，
    新手不知道选哪个（其实 90% 场景是前者）——后者可收进「更多」。
13. **缩略图角标 tags（标准图/最新/高清）无图例**，第一次看不懂颜色含义。
14. 窄屏下 split2 堆叠后右列结果在很下面，检索完要滚很久才能看到结果。

## 修复优先级建议

| 批次 | 内容 | 理由 |
|---|---|---|
| 第一批 | #1 #2 #3（结构对齐报告流水线） | 不修的话用户始终在错误的认知模型里操作 |
| 第二批 | #4 #5 #6 #7（高频操作体验） | 每次取材都要受的罪 |
| 第三批 | #8 + P2 清单 | 防御性 + 打磨 |

其中 #2（柜联动）改动最小、收益最大：①选柜 → ②自动载入该柜编码 + 锁定检索
范围到该柜批次，一步消掉三个问题（#1 #2 大半、#3 的口径）。
