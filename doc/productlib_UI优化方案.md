# 产品库 Web 端 · 界面全面优化方案

> 范围：`tools/productlib/web/index.html`（单文件应用，CSS+HTML+JS 共 1759 行）
> 现状定位：功能齐全（六页、30+ 接口、标准图编辑器、报告导出均已跑通），但 UI 是**逐轮加功能堆叠**出来的，缺乏统一设计系统与主线流程。用户反馈「页面/交互/布局/流程/显示都有重大问题」，本文据此给出可落地的优化方案。

---

## 一、审计发现（按问题域归类，均可在代码中定位）

### 1. 信息架构 / 导航
- **六页平铺、无主线**：`概览 / 标准库·产品 / 审核队列 / 预检批次 / 报告素材 / 设置` 是并列 tab，但真实工作流是「导入→治理→审核→检索→报告」一条线。tab 之间无「当前在哪一步、下一步去哪」的引导。
- **概览页是两张静态说明表**（L262-300）：与 tab 重复显示状态，且是文字墙，不像「应用首页」而像「帮助文档」。它不驱动流程。
- **导出面板嵌在产品页底部**（L350-362）：浏览与导出两类职责混在一页。
- **「标」角标（has_standard）是好设计但被埋没**：仅产品行与照片卡小角标，没有在导航/概览层形成「标准库成熟度」的可见信号。

### 2. 布局 / 呈现
- **两套蓝、调性不一**：主强调色 `--accent:#1f6feb`，但「标」标签/角标/标准图编辑器描边用了另一种蓝 `#0b5cad`（L204-216、L1661）。同一语义两种蓝 = 视觉不一致。
- **报告页缩略图过小**：`.rp-shot` 宽 132px、缩略 96px（L192-194），理由文字 `-webkit-line-clamp:2` 易截断关键信息。
- **照片卡信息密度失衡**：`.shot .meta` 两行各 11px（L91-92、L955-958），文件名+时间+MB+关联+状态全堆在底部，小图下阅读困难。
- **按钮层级不清**：面板里常 4~5 个按钮并排（如治理面板 L402-410），主操作（开始治理）与次要（重跑/选项）视觉权重无差。
- **无统一间距与容器节奏**：面板 padding 16、卡片 14、若干行内 `margin-top:18px` 硬编码（L471、L487），缺乏间距标尺。
- **响应式只做了 split 在 900px 折叠**（L119），1200~900 之间表格会出现横向滚动。

### 3. 交互 / 操作流程
- **没有「本批预检工单」的一体化进度**：治理有进度条、导入有 toast，但**没有一个地方把「某批：已导入→已治理→已审核→可出报告」串成一眼可见的状态**。
- **审核是 12 张一批 + 「换一批」**（L1177-1234）：面对真实库 1200+ 待认领照片，纯逐张点效率极低，**缺批量操作**（如「全部按推荐候选批量关联」「本页全部忽略」）。
- **发现新产品 / 合并建议缺批量确认**（L1278-1399）：每张卡单独「确认入库/并入」，无「全部确认」。
- **报告导出目录每次手填**（L536）：无默认值/上次记忆。
- **键盘可达性差**：仅输入框回车、Esc 关弹层；网格无方向键导航、无 `/` 聚焦搜索。
- **近标准图功能「看不见」**：仅当产品已有标准图才生效，而当前库 0 个产品做过标准图 → 该功能对用户等于不存在（发现性缺口）。

### 4. 显示一致性 / 反馈
- **空状态是灰字**（L335、L379、L466 等 `.empty`），无插画、无操作引导，与「要求补充空状态」的初衷有差距。
- **长操作反馈弱**：导入/治理靠单行 toast；大目录导入（249 张）期间页面无骨架/进度，易误以为卡死。
- **toast 单次即消失**（err 6s / 其它 3.2s），连续操作会互相覆盖。

## 二、改进方案总览

### 设计系统（统一，杜绝「两套蓝 / 硬编码间距」）
- 收敛为**单一强调色**（保留蓝 `#2563eb`，删除 `#0b5cad` 分支，标类改用语义色）。
- 建立**间距标尺**（4/8/12/16/24）、**圆角标尺**（6/10）、**阴影一层**、**字号阶梯**（12/13/14/16/26）。
- 按钮三级：`btn`（主）/ `btn.ghost`（次）/ `btn.sm`（紧凑），每页仅 1 个主 CTA 高亮。
- 统一 `.panel` 内边距与卡片风格，删除散落的 `margin-top:18px` 硬编码。

### 信息架构（保留六页，但补一条「主线」）
- **概览改造为「预检工单仪表盘」**：顶部一条**横向流程步骤条**（导入→治理→审核→检索→报告），每步实时显示状态（待办/进行中/完成）并可点击直达对应页；下方为支撑统计与边界提示（压缩为折叠区）。
- 标准库成熟度在概览与产品页以「已做标准图 N / 共 M」徽标呈现。
- 导出从产品页底部**移到报告素材页或独立设置项**，产品页专注「浏览+审核」。

### 每页改造清单
| 页 | 关键改动 |
|---|---|
| 概览 | 流程步骤条（主线）+ 实时状态；统计卡保留；边界提示折叠 |
| 标准库·产品 | 左清单加「仅未做标准图」筛选；右详情清晰化；导出面板移走；空状态带 CTA |
| 审核队列 | 三段各自加**批量操作条**（全选/批量关联/批量忽略）；计数徽章保留 |
| 预检批次 | 批次表保留；治理面板主 CTA 高亮；导入进度可视化（骨架+百分比） |
| 报告素材 | 缩略图放大至 160px、理由完整展示（悬浮+常显首条）；导出目录记忆；结果数置顶；导出按钮吸底行动条 |
| 设置 | 基本不变，跟随新设计系统 |

### 关键交互重设计
1. **常驻流程步骤条**：在概览与每页顶部轻量显示当前阶段，点击跳转；让「导入→…→报告」成为一条看得见的主线。
2. **空状态升级**：插画式图标 + 一句说明 + 一个主操作按钮（如「去导入照片」「去跑治理」），而非灰字。
3. **批量操作**：审核队列/发现/合并三处加「批量确认/批量忽略/按推荐批量关联」；报告导出支持「全选本批建议采用」。
4. **反馈增强**：长操作（导入/治理/导出）用**行内进度 + 百分比**替代单 toast；toast 同类型合并、不互覆盖；加载区用骨架占位。
5. **报告导出目录记忆**：localStorage 记上次目录，预填。
6. **键盘**：`/` 聚焦搜索；Esc 关弹层（已有）；网格方向键可选（增强项）。

### 兼容性与数据迁移
- **纯前端 UI 改动**，后端接口、数据库、CLI、selftest 全部不动。
- 原始文件不动原则不变；标准图/链接/导出逻辑不变。
- 无数据迁移需求。

### 验证方式
- `node --check` 校验 JS；id 引用一致性脚本校验（沿用既有）。
- 临时库回归：既有 API 行为不变（用 selftest + 上轮 `_test_*` 思路快速冒烟）。
- 真实库冒烟：六页逐一打开、走通「导入→治理→审核→检索→导出」主流程；截图核对布局。
- 端到端验证清单：①流程条五步状态实时 ②审核批量关联 ③报告导出含 report.html ④空状态有 CTA。

## 三、待确认的关键设计（见对话内提问）

1. **导航走向**：保留六页 + 加常驻流程条（低风险、立竿见影） vs 重构为「工单式单线流程」（改动大）。
2. **视觉风格**：清爽浅色·克制蓝（推荐） / 现代中性灰+单一强调色 / 信息密集工具风。
3. **执行范围**：本轮一次性全量做完（推荐） vs 先 IA+设计系统+概览/报告两页再迭代。
