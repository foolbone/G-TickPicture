## 真实数据桌面预演（02:17~02:55，老板给了 PIDU9352234 清单+249 张照片）

**探针抓掉 2 个真机必现 bug + 1 个可用性缺口**：
1. det 输入必须 **32 对齐**（U-Net 跳连 Add 要求；61×62 直接广播崩 → 每张都静默回退 ML Kit）。Kotlin 的 round32 原本就对，探针同步修正。
2. 塑料袋反光让装箱单出 300+ 误检框（PC 逐框 rec 16s）→ Kotlin 加 `MAX_REC_CROPS=40`。
3. **倒贴标识卡**：det 对倒置文字无感，rec 0° 全乱码、180° 满分 → Kotlin rec 加**四方向兜底**（`FOUR_DIR_CONF=0.85`，低置信度才试 180/90/270）。
4. 清单导入：真实清单箱号是**稀疏填写**（合并单元格视觉）→ importer 加**向下填充**（只在编码非空时更新 carry，NOTE 行不污染）；`Model Number` 不含 'no'/'code' 子串 → itemCode 关键词补 `modelnumber/modelno`。

**基线数据**（70 万像素档）：249 张 0 失败；照片命中率 2.8%（7 张全是装箱单近拍，一张最多命中 13 编码，0.94~1.00）；清单覆盖率 21%；det 0.66s+rec 0.75s（PC）。**像素预算实验 70万/200万/400万命中无差异 → 70 万维持**。低命中真因 = 照片内容多为外观/人物/空箱，不是引擎问题。

## 真机缺陷修复（老板反馈两条，03:00~03:35）

老板真机截图反馈：「1、在整理时，无法看到已经指派的照片，导致无法修改。2、OCR增强不可用，标准版不起作用，没有一张图片被识别出来。」

### 缺陷①：整理页看不到已指派照片、无法修改 —— 根因是两半，都修了
1. **可见性**：`organize_repository.watchOpenGroups` 的 where 是 `itemId.isNull()`，一确认就从流里消失（v3.1「只显示缺口」的副作用）。修法不是塞回待办流，而是**并行第二条流** `watchAssignedGroups`（查 `itemId.isNotNull()`，按 `confirmedAt` 倒序）+ 整理页 `SegmentedButton` 页签「待处理 N 组 / 已指派 N 组」。新增只读投影 `domain/model/assigned_group.dart`（不给 OpenGroup 加归属字段，两视图语义保持分离）。
2. **可修改性（真 bug，测试抓出）**：`assign_service.revokeGroup` 写的是 `itemId: Value.absent()` —— drift 语义是**跳过该列不更新**，撤销对归属是**空操作**（assignments 吊销了、itemId 原样留着）。改 `Value(null)` 后新增仓储测试转绿。全库排查：手写代码里 `Value.absent()` 仅此一处。
3. 撤销/改派均走 `AssignService`，架构规则 3 未破。改派 = 撤销 + 立即弹归属选择。

### 缺陷②：OCR 增强不可用 / 标准版也不识别 —— 可确定的全修，并把失败原因做成 UI 可见
1. **ML Kit 脚本换 `chinese`**（原 `latin`）：现场标签中文为主，拉丁模型对整行中文版面切分差；与 build.gradle 引入 `text-recognition-chinese` 的本意一致。
2. **PP-OCRv6 不可用必须给原因**：`isReady` 契约改回传 `Map{ready, reason}`（兼容裸 bool 旧契约）；Dart 侧 `PpOcrV6Extractor.lastUnavailableReason`；Kotlin 侧 `OnnxPpOcrEngine.lastCreateError` 逐步记因（模型缺失 / materialize 失败 / ORT 环境 / det session / rec session / 字典不匹配）+ `Log.e(TAG="PpOcrV6")`。
3. **失败照片可恢复**：`suggest_pipeline.retryFailedPhotos()`（failed 标回 pending 重跑）+ 设置面板「重试失败的照片」+ `StreamController.broadcast` 广播进度（设置面板发起的重试也能推进度到页面）+ `_running` 防并发锁。
4. **UI 不再把「识别崩了」说成「没有编码」**：`OpenGroup` 加 `ocrPendingCount/ocrFailedCount`，组卡三态分述（识别失败 → 提示去重试 / 识别中 / 没匹配到）。
5. **资产压缩**：`androidResources { noCompress += "onnx" }`（压缩资产只能流式解压，各 ROM AssetInputStream 实现不一）；`materialize()` 优先 `openFd().length`，退回 `available()` 只当猜测并校验非零。
6. **effective 引擎广播修复**：`_applyPreferredEngine` 加 `publishEffective` 回调，连 ML Kit 默认分支也广播（旧版 `return` 导致设置面板 effective 永远停在初始值）。

### 相册镜像（复制，不是移动）
- **决策：App 私有副本是交付源，永不交给 MediaStore 托管；相册里放副本**给现场发微信用。原件删了相册还有，反之不成立。

- **`GalleryService`**（domain/capture）四纪律：复制不移动 / 失败一律静默（返回 false+reason，不 throw 不弹窗）/ 开关默认开 / 主路径零改动（快门→落盘→入库完全相同，相册写入在 `_shoot` 之后 unawaited）。权限探测结果缓存（连拍不能每张问一次通道）。
