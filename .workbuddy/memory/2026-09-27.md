## 标准产品库运营闭环（11:51，老板五条场景规划后执行）

老板五条：①产品库=人工确认审核的标准库 ②来源=初始清单+每批新照片 ③新批次→系统提取→人工审核入库 ④确认后本地落盘（编码+类别标识命名） ⑤编码双来源（清单/图片识别），两边都有→合并建议→人工确认。

设计落点：
- **review_state**：products 加列（SCHEMA + connect()._migrate 老库 ALTER 补列 DEFAULT 'confirmed'——存量来自清单/人工视为已审核）。清单导入与 discover 确认都写 confirmed。UI 只在非 confirmed 时标「待审核」（平时零噪音）。
- **三条人工闭环**（新批次照片进来后）：发现新产品（库外编码，已有）→ 合并建议（库内编码匹配，新增，产品视角聚合）→ 人工关联工作台（自由认领，已有）。exact 自动关联保留（效率，之前拍板），合并建议只收「尚未关联」的模糊命中——恰是「读出来像但不敢自动写」的那批。
- **合并建议**：`store.merge_suggestions()` 按 code_norm 聚合（vision_codes + OCR token 匹配 CodeIndex，exact/fuzzy 分桶）；`confirm_merge()` 批量建 links（source=manual, evidence='合并建议人工确认'）。接口 GET /api/merge-suggestions、POST /api/merge/confirm。
- **标准库落盘**：`store.export_standard()` 把 confirmed 产品的关联照片复制到指定目录，命名 `{code}_{标识卡|产品|包装}[_n].jpg`（第1张不带序号，按 taken_at 稳定排序→重复导出幂等；code 内非法文件名字符替换 _），附 standard_index.csv（utf-8-sig）。接口 POST /api/export/standard。设置页加导出面板。

**踩坑（重要）**：`BL.CodeIndex.best()` 返回元组首位是**原始 code 而非 code_norm**——拿它当 code_norm 回查 products 会因大小写不一致查空（103011013388A vs 103011013388a）。回查必须 `WHERE code_norm=? OR code=?` 双路。

验证：临时库全链路 ALL_PASS（迁移/建议/确认合并/建议消失/导出命名/CSV 行数/幂等）；真实库 556 产品全部 confirmed、**合并建议 14 个产品**（全模糊命中，等老板裁决）、导出 8 产品 11 张+CSV 文件名规范正确；node --check JS 通过；server 已重启，/api/merge-suggestions 实测返回正常。库已涨到 1466 张照片（新批次导入），pending 1214 待治理——治理后建议/候选自动吸收。

## 相机路径分组 BUG 修复（老板纠偏：「不是微信导入的，是相机拍摄的」）

微信那套根因（EXIF/mtime）对相机路径不成立——相机照片 takenAt = DateTime.now() 本来就准。真实根因是**三重叠加**：

1. **实时触发 × 幂等跳过（最直接）**：整理页数据驱动补组（未入组数 > 0 立即跑），而 `_regroupPendingOnce` 旧口径「已入组一律跳过」→ 拍第 1 张立刻立单张组，20s 后第 2 张来了第 1 张已被跳过，永远各立一组。时序聚类只在「一批照片同时未入组」时有效。
2. **退出再进切批次**：`_onFinish` 会 endSession，下次 startSession（旧）永远新开批次；聚类按 sessionId 分桶（组表 sessionId 外键）→ 跨批次永不同组。现场「拍一件→对照清单→再拍」恰恰就是 20 秒级退出再进。
3. **默认关**（09-26 拍板）：老板的使用预期是开 → **AskUserQuestion 确认后改默认开**（无设置记录 = 开，`value != '0'`）。

### 修复
- `_regroupPendingOnce`：开关打开时直接转 `_regroupByTimeOnce`（全量口径：未指派单张组 + 游离照片一起重新聚类，与手动按钮同口径）；关闭时维持单张成组。
- **批次续接窗口**：`AppConst.sessionResumeWindow = 5min`；仓储 `startSession` 内置续接语义（open → 续；camera 批次 5min 内结束 → `reopenSession` 复活续用；album 永远新开）。**续接放仓储而不是服务层**——首轮实现放服务层导致测试直调仓储时全不生效，3 个测试失败暴露后下沉重构。
- `CameraCaptureService.startSession` 简化为纯委托 + 从 photoCount 恢复会话计数。
- 整理页面板 onToggle：打开开关立即跑一轮 regroupByTime（旧单张组马上归位）；面板文案「默认：」改「已关闭：」（默认值变了）。
