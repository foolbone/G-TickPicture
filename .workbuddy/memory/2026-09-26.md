## 历史预检照片产品库（P1）方案 + 建库工具原型

### 需求
老板提出：利用历史预检的照片和报告建立产品库，将来某产品漏检时用以前相同产品的照片补充。
素材：`doc/PIDU9352234/`（249 张照片 + 清单 xls + 报关资料 xlsx），原始未整理。

### 方案要点（已交付给老板，见对话记录）
- 两阶段：**建库（PC 一次性，可灰度，不动 APP 主链路）→ 用库（APP 内叠加，不替换三段式）**。
- **第一约束**：历史照片不能证明"本次货物状态"，只能证明"历史上这个编码长什么样"。
  复用进交付包必须逐张标来源（文件名后缀 `_L`、对照表加「照片来源」列、缺口报告分段），
  最终是否采用由报告员决定。
- **不新增写归属的入口**：复用照片落成 `capture_session(source='library')` 的普通照片，
  走现有整理页，`AssignService` 不动 → `orphanCount` 不变式 / manifest / 对照表免改。
- 产品库存储格式**刻意与 M5 交付包同构**（平铺 + 文件名自带身份 + 对照表 + manifest），
  复用进新包时零格式转换。
- 主键 = `归一化(编码)`，粒度 = 编码 × 拍摄时间实例（跨时段必须并列展示让报告员挑）。

### 工具（P1 原型已完成）
新增 `tools/build_library.py`（建库）、`tools/verify_library.py`（8 条断言自检）。

用法：
```
python tools/build_library.py --photos doc/PIDU9352234 --out library \
    --customs "doc/PIDU9352234/MX-...-报关资料.xlsx"
python tools/verify_library.py --db library/library.db --csv-dir library
python tools/build_library.py --photos ... --out library --apply-review library/_待复核.csv
```

产出（`library/`）：`library.db` / `_编码对照表.csv` / `_待复核.csv` / `_建库报告.md` /
`manifest.json` / `_ocr_cache.json`。

绑定强度四级：`A_strong`（既往交付对照表，直接用）/ `B_ocr_multi`（单张命中≥2编码）/
`B_ocr_single` / `C_adjacent`（时序推断，**不算证据，不计入 photo_count**）。

### 实测结果（PIDU9352234，2025-04-05 作业）
- 249 张（MD5 重复 13 → 唯一 236）· 902 MB · 55 组
- 清单 89 行 → **81 唯一编码**；报关单主 sheet 表头第 11 行 → 81 唯一料号；
  **两份编码集合完全一致（交集 81），可互相印证**
- OCR 236 张 · 86.0% 有文字 · **仅 10 张（4.2%）命中清单编码**
- **入库 28/81 编码（34.6%）**，其中 **23 个只来自 2 张装箱单近拍**（各命中 13 编码）
- 无照片 53 个编码中 **35 个集中在 BOX-M22、13 个在 BOX-M12**（90%）→ 整箱缺失，非零散漏拍
- 跨时段编码 7 个 → 召回须并列展示

### 开发中抓到的 5 个真实缺陷（都是跑真实数据才暴露的）
1. **float 编码尾零**：xls 里 `1000000119` 存成 float，`str()` 得 `'1000000119.0'`，
   归一化后变 `10000001190` → 与报关单文本型对不上，编码交集凭空少 1。
   修法：`_cell()` 对整数性 float 去小数点尾零，**不用 int() 转换**（长编码超 2^53 丢精度）。
2. **备注行漏检**：`NOTE.` 落在**箱号列**而非编码列，只查编码列会静默丢行且 `note_rows=0`。
   修法：扫整行。
3. **C_adjacent 泛滥**：初版"同组有命中就全标 C"→ 106 条，出现「11 张照片 1 个编码」的噪声。
   修法：仅当组内 B 级照片 ≤2 张（同一目标连拍形态）才生成，且每组上限 4 张 → 74 条。
4. **OCR 结果未落盘**：调参必须重跑 13 分钟。修法：缓存到 `<out>/_ocr_cache.json`，
   二次运行 **700s → 5s**。
5. **`_待复核.csv` 预填动作值被当人工决定**：预填 `确认`/`核对` 导致"只改 5 行却回写 31 条"。
   修法：**动作列预填为空**（留空=跳过，只有人亲手敲的字才算数），
   `apply_review` 用 `cursor.rowcount` 报告实际影响行数 + 非法动作白名单拒绝。

  （1x/2x/5x，`AppConst.zoomStepCandidates` 滤掉超镜头能力的；maxZoom≤1.05 或只有一个档时整列隐藏）；

  映射为纯静态 `presetFor`。preset 只能初始化时给定 → 切画幅**先关后开重建控制器**
  （同一摄像头无法双开；与 _openController 的「先挂新再 dispose 旧」相反），失败兜底重开一次，
  UI 全屏收黑 + HUD。选择落 SP 键 `camera.aspect_ratio`，跨会话生效。
- **闪光**：顶栏一键循环 关→自动→常亮(torch)，落 `camera.flash_mode`；默认仍 off

- **网格线**：FrameOverlay `grid` 参数画全屏三分线（alpha 0.16 不抢戏），面板开关，默认关。
- **设置面板**：顶栏 tune 图标 → 深色底部面板，只放画幅+网格；闪光是高频动作放顶栏。
  识别/归属入口仍禁止（§5.2 不动摇）。
- **顺手修复**：采集页构造 CameraCaptureService **漏传 gallery**（页内直接 new，
  `captureServiceProvider` 定义了但从未被用）→ 相册镜像在采集页实际没生效。
  已补传 gallery + prefs，并注明不走 provider 的原因（页内自管生命周期，autoDispose 需持续 watch 保活）。
- **曝光补偿重放**：_openController 每次开控制器重放 `_exposure`（换镜头/画幅后不再丢）。
